# AI x Ahmad: researched improvement review

Reviewed 8 October 2026. This review covers the local project, collection pipeline, content agents, Studio, and GitHub workflows. Priorities and effort are engineering judgments; external references below support specific technical recommendations. The deployed Firebase rules and live cloud runs were not inspected.

The best next investment is reliable, traceable news: readers should see when information was collected, why it matters, and which source supports it. The project already has useful foundations: parallel collection, duplicate grouping, source packs, a manual publishing step, retention, and a working test suite.

At the start of this review, the local `news.db` snapshot contained **13,242 stories**. Its latest collection timestamp was **1 October 2026, 18:10 PKT**, over six full days before the review date; **475 stories lacked a publication date**. These figures describe the snapshot inspected during the review, not the current synchronized database or necessarily the deployed site. Subsequent synchronization restored newer upstream collection data, with the latest collection timestamp at **8 October 2026, 06:54 PKT**, and both HTML pages were rebuilt from that snapshot. Rebuilding HTML alone does not make stories current.

**Implemented in this update:**

- The public news site has a refreshed editorial layout, clearer topic navigation, responsive story cards, reading-list controls, and improved mobile search/navigation.
- Studio now surfaces the next useful task, shows collection age separately from build time, offers story-date filters and a saved card/list preference, and makes collection trends searchable.
- RSS publication dates now use UTC conversion instead of host-local `mktime()`.
- Article extraction now accepts the database's alternate-link objects as well as string URLs, skips unusable or duplicate links, tries valid backup publishers, and attributes the source pack to the publisher supplying the extracted text. Regression tests cover this data flow, publisher attribution, and UTC dates.

**1. Authenticate Studio database access.** `README.md` acknowledges permissive Firebase rules. `agents/store.py` and the Studio read and write Realtime Database through unauthenticated REST requests; the passcode currently gates the interface and derives a database path. In local mode, `docs/pipeline.json` is served as a static artifact, so that screen gate cannot protect its unpublished drafts. Use Firebase Authentication, owner-scoped `.read`/`.write` rules, and `.validate` checks for permitted statuses and record shapes. Give the cloud pipeline a server credential and expose only approved public data. Verify access with Firebase emulator tests for signed-out requests, another user, and malformed writes. Firebase enforces access through server-side rules associated with authenticated identities. [Firebase security rules](https://firebase.google.com/docs/database/security).

**2. Monitor the whole collection run.** The UI now distinguishes story collection time from the page build and shows when the saved collection is old. Remaining gap: `.github/workflows/fetch.yml` hides a failed free triage command with `|| echo "triage skipped"`, and `fetcher.run_fetch()` persists health only for agent discovery adapters. A successful site build or one newly saved story can therefore conceal missing inputs or an empty Ideas inbox. Persist the last attempted and successful collection, successful/failed feed counts, and stage results. Alert after a configurable stale interval, such as three missed hourly cycles. Extend the existing adapter-health mechanism to every feed. GitHub says scheduled jobs can be delayed and, under sufficient load, dropped, so an hourly cron is not an hourly freshness guarantee. [GitHub scheduled events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

**3. Strengthen the evidence behind each claim.** The alternate-link shape and source-pack attribution issues found in the audit are fixed: enrichment can now use `{url, source}` objects from `database.add_link_to_item()`, try valid backup URLs, and preserve the supplying publisher's label. Remaining gap: `agents/verify.py` accepts bare-number matches and allows generated angle text as support: source text saying “32 clinics” produced no number error for a draft claiming “32% improvement.” Preserve units and attach each factual claim to an actual source quotation and URL. Treat deterministic checks as screening, and flag missing or failed fact-checks clearly. Consider requiring an explicit recorded override before approving drafts with unsupported claims. These recommendations follow the emphasis on provenance and output evaluation in [NIST's Generative AI Profile](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence).

**4. Finish timezone consistency.** `fetcher._entry_published()` now uses `calendar.timegm()` for feedparser's UTC tuples; the publication-date shift is fixed. Remaining gap: `main.maybe_send_nudge()` adds the configured `+5` offset to `datetime.now().hour`, even when the workflow already uses Karachi time. Use `ZoneInfo('Asia/Karachi')` once. Studio already stores selected schedule instants as ISO UTC timestamps, but recurring slots follow each browser's local timezone; persist the creator's chosen timezone for those slots. Verify notification quiet hours and a scheduled post across two browser timezones. [Feedparser date parsing](https://feedparser.readthedocs.io/en/releases/date-parsing.html), [Python UTC tuple conversion](https://docs.python.org/3/library/calendar.html#calendar.timegm).

**5. Protect edits across devices.** `Store.patch()` builds a full record from its loaded snapshot, and `Store.flush()` sends that record at a collection child path. That can overwrite fields edited after the snapshot was loaded. Studio `patchDoc()` uses smaller patches, but a successful request deletes the pending override for the whole record; an older request acknowledgment can clear a newer pending edit. Queue saves per record, clear only the acknowledged mutation, add a record revision, and surface conflicts instead of silently choosing a browser clock timestamp. Firebase REST supports ETag conditional writes with `PUT`/`DELETE`; `PATCH` does not provide that transaction mechanism. Test a slow acknowledgment, an offline edit, and an agent update overlapping a browser edit. [Firebase conditional writes](https://firebase.google.com/docs/database/rest/save-data#section-conditional-requests).

**6. Make cost controls match their wording.** `PIPELINE_DAILY_BUDGET_USD` resets through a new `LLM.spent` value every process, so it behaves as a per-run threshold. The check occurs before a call, allowing the next request to exceed the remaining amount. `agents/llm.py` also combines ordinary input, cache reads, and cache creation at one input tariff, although they have different prices. Rename the setting to a per-run budget or persist a daily ledger; reserve estimated request cost, cap output to the remaining budget, and record actual model and token categories, including fallback responses. Keep free mode as the default. Validate cost accounting with mocked usage and repeated runs on the same day. Use the provider's current table for cache and model pricing. [Claude API pricing](https://platform.claude.com/docs/en/about-claude/pricing).

**7. Explain evidence rather than overstate confidence.** `scoring.audience_score()` gives points for every extra URL, so several syndicated articles can outweigh independent reporting. Count distinct normalized publishers and separate first-party announcements, reported outcomes, community discussions, and preprints. Add a small “Why this was selected” explanation using the existing score reasons. In Pulse, `momentum.label()` calls an item with no history “rising,” and YouTube autocomplete enters with no measured volume; distinguish new signals, observed growth, and suggestions. Show sample size and source coverage before adding more platforms. Use saved/published/rated posts to tune topic preferences; test changes on a small labeled set of duplicates and useful stories. This is a product recommendation, not evidence that current ranking has been evaluated against reader outcomes.

**8. Check each release and measure the reading experience.** The three workflows collect or generate outputs but do not run the existing tests before publishing them. Add a separate pull-request check for Python tests, JavaScript syntax, Studio flows, and generated output consistency. Maintain real-browser coverage for mobile layouts, keyboard navigation, visible focus, modal focus return, text contrast, and reduced-motion behavior. Use WCAG 2.2 AA as the accessibility target: normal text generally needs 4.5:1 contrast, focused controls must remain visible, and pointer targets need the required size or spacing exceptions. The visual refresh now improves reading hierarchy and discovery controls; measure it with five practical tasks: find a recent story, inspect its source, save an idea, edit a draft, and schedule it. Keep frequent writing actions visible and less-used pipeline configuration behind details controls, following [NN/G's progressive disclosure guidance](https://www.nngroup.com/articles/progressive-disclosure/). Pin Actions to reviewed commit SHAs and pass workflow inputs through environment variables rather than interpolating them into shell source. [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [GitHub workflow security](https://docs.github.com/en/actions/reference/security/secure-use).

Next, prepare the authentication migration while adding collection monitoring and stronger claim verification. Track collection success rate, age of the newest source, thin-source percentage, unsupported-claim rate, and time from saved idea to approved draft. Then use actual post outcomes to improve relevance.
